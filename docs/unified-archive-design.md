# 統合アーカイブの設計

対象: 5種のアーカイブ（`.score` / `.coursework` / `.grade` / `.asb` / `.students`）を1つにまとめる。
#1077（取り込む JSON の実行時検証）と #1308（取り込み前に成績算出への影響を出す）を内に含む。
検討日: 2026-10-04。着手は段階ごと（§10）。

`docs/import-export-architecture.md` は、統合版のファイルの道案内と、読み込みだけの凍結した形式として
残る旧5種の要点と、スキーマを変えたときの手順を書いた文書である（段階6で統合版を正本に書き直した）。
`docs/remaining-work.md` にあった段階60（取り込みの規則を寄せる）と判断待ち #12（書き出しの入口を
1つにまとめる）は、本書が置き換えた。

---

## 1. なぜ1つにするか

- **種ごとに形も規則も違う。** 照合が id 一次の種と名前一次の種がある。3択（上書き / 統合 / 別で
  追加）は試験が3つ、生徒が2つ、資料は「別で追加」が名ばかり、成績と解答用紙には無い。同じ
  ものを取り込み直すと、成績と解答用紙は毎回複製される（§3.3）
- **スキーマを変えるたびに5種を手で追う。** アーカイブの型は Prisma の型の手書きの写しで、
  書き出しはフィールドを1つずつ写している。版をまたぐ変換器が5種で計44本ある
- **成績アーカイブは、使う試験・資料を名前で参照するだけ**で、取り込み先に同名のものが在る
  ことを前提にしている。在る前提が崩れると、評価項目が黙って欠ける

## 2. 決まっていること（OWNER 裁定 2026-10-04）

| 論点                                            | 裁定                                                                                                                                                        |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 中身の形式                                      | **SQLite**。選んだ範囲を、現行スキーマと同じ DB に行ごと写して ZIP に入れる                                                                                 |
| 旧5種                                           | **読み込みだけ残して凍結**。書き出しは統合版に一本化                                                                                                        |
| 範囲の選び方                                    | 1画面のチェックボックスで、4種の実体（試験・資料・成績算出・解答用紙定義）と共通の実体（生徒・学級・小計グループ・タグ）を選ぶ                              |
| 既定の範囲                                      | **関連するデータを全て含める**（2026-10-04 追加）。本来関連するデータを利用者の意向で外すときは、外したことと、それで何が書き出されないかが分かる画面にする |
| 成績算出が使う試験・資料                        | **必ず含める**（外せない）。名前参照はやめる                                                                                                                |
| 採点                                            | **全員分か本人分かを画面で選ぶ**                                                                                                                            |
| 照合                                            | **原則 id**。id 以外（学籍番号・名前など）での照合は付加機能                                                                                                |
| 値の扱い                                        | 既存の3択（`importValuePolicy.ts`）を全行に例外なく適用する                                                                                                 |
| `@@unique` の衝突                               | id は違うが一意キーが同じ行。3択に従い、上書き・統合のときは**採用する id を利用者に選ばせる**。版をまたいで必ず起きる衝突は利用者に案内する                |
| migration での決定論的 id                       | **禁止**（id は不透明な uuidv4）                                                                                                                            |
| 「どの行がどの migration で生まれたか」の記録表 | **作らない**。一意制約の衝突として拾う                                                                                                                      |
| 拡張子                                          | **`.sao`**                                                                                                                                                  |

## 3. 現状（2026-10-04 実測）

### 3.1 書き出し

| 種            | 入口                                         | 範囲の選択                          | 結果の表示                                |
| ------------- | -------------------------------------------- | ----------------------------------- | ----------------------------------------- |
| `.score`      | 試験一覧の行メニュー・試験詳細・一覧での一括 | 3モード（全部 / 雛形 / 雛形＋小計） | `ExportResultSummary`（欠けた画像・失敗） |
| `.coursework` | 資料一覧・詳細                               | 無し                                | 成功トーストのみ                          |
| `.grade`      | 成績一覧・詳細                               | 無し                                | 無し                                      |
| `.asb`        | 定義一覧・詳細                               | 無し                                | `ExportResultSummary`                     |
| `.students`   | 生徒表で選択                                 | 学級のチェックボックス              | —                                         |

試験の書き出しの範囲（`export/exam-archive/dataCollector.ts`）:

- 採点（`QuestionScore` と注釈・`CompoundAnswerScore`）は**書き出す本人の分だけ**
- 確定（`ScoreDecision`）・担当（`CropRegionAssignment`）・返却版（`ReturnSnapshot`）は全員分
- 試験のメンバー（`UserExam`）は書き出さない
- 在籍は、受験生の**全学級分**（試験と関係ない学級も入る）

### 3.2 画像・ファイル

DB の列はデータディレクトリからの相対パスを持つ。

- 模範解答: `ExamPage.imagePath`。アプリで登録すると `exams/{examId}/master-answers/…`、
  取り込むと `exams/{examId}/master-images/…` になり、置き場が2系統ある
- 答案: `StudentAnswerImage.imagePath`。`exams/{examId}/answer-sheets/…`
- 解答用紙の画像: `AsbImageElement.imagePath`。`answer-sheet-builder/{定義id}/images/…`

書き出しは ZIP へファイル名だけにして平置きし、取り込みでパスを組み直している。

### 3.3 取り込み

| 種            | 画面                               | 3択                       | 照合                                                                          | 取り直すと     |
| ------------- | ---------------------------------- | ------------------------- | ----------------------------------------------------------------------------- | -------------- |
| `.score`      | ウィザード（概要 → 紐づけ → 確認） | 3つ                       | id 一次。生徒・学級・小計グループ・利用者は名前などで紐づけ可。タグは名前が先 | 同じ試験に統合 |
| `.students`   | ウィザード                         | 2つ（別で追加なし）       | 試験と同じ                                                                    | 統合           |
| `.coursework` | ダイアログ1枚                      | 3つ（別で追加は効かない） | 資料は id か同名候補。生徒・学級は自動                                        | 統合           |
| `.grade`      | ダイアログ1枚                      | **無し**                  | 参照先は名前                                                                  | **毎回複製**   |
| `.asb`        | 無し（即取り込み）                 | **無し**                  | —                                                                             | **毎回複製**   |

- `@@unique` で衝突した行は、今はどこでも**既存の id が黙って勝つ**
- 試験の取り込みは、画像を DB のコミット後にコピーする。既にあるファイルは上書きしないので、
  「上書き」を選んでも画像は置き換わらない（選択肢の説明と食い違う）
- 試験の取り込みで、紐づけ方針が「名前」のとき、取り込み前の競合検出と実際の投入で生徒の
  向き先がずれうる（`scoringConflictDetector.ts:247` と `studentProcessor.ts:196`）

## 4. ファイルの形

```
<名前>.sao  (ZIP)
├── manifest.json
├── archive.db          現行スキーマと同じ SQLite。_prisma_migrations を含む
└── files/              データディレクトリからの相対パスのまま
    ├── exams/{examId}/master-answers/…
    ├── exams/{examId}/answer-sheets/…
    └── answer-sheet-builder/{定義id}/images/…
```

`manifest.json` が持つもの（型は `src/types/unifiedArchive.types.ts` の `UnifiedArchiveManifest`）:

- 形式の識別子（`format`）と形式の版（`formatVersion`。ZIP の構成が変わったときだけ上げる。
  スキーマの版ではない）
- 書き出したアプリの版（`appVersion`）
- `archive.db` に適用済みの最後の migration 名（`lastMigration`）
- 書き出し時刻（`exportedAt`）と書き出した利用者の id（`exportedByUserId`）
- 選んだ範囲（`selection`）: 根と直接選んだ共通の実体の id（表名ごと）、採点の範囲（全員 / 本人）、
  採点と答案を含めるか、選べる項目（§5.5）。既定のままでも明示して書く
- 表ごとの行数（`rowCounts`。0 の表と `_prisma_migrations` は載せない）
- **利用者が外したもの**（`exclusions`）: 外した行の id と、外したことで入らなくなった表ごとの
  件数。取り込み側はこれを見て、「このアーカイブには〇〇が含まれていません」と示す（無いことを
  削除と読まないため）
- 同梱したファイルの数と、DB が指すのに同梱できなかったファイル（`files`。見つからない /
  データディレクトリの外を指す）。欠けても書き出しは止めない

**スキーマの版は `_prisma_migrations` そのもの**で、`*_CURRENT_VERSION` も変換器も持たない。
画像を DB と同じ相対パスで置くので、取り込みはパスを組み直さずに済む（「別で追加」を除く。§7.4）。

### 4.1 受け取った DB を開くときの守り

アーカイブの DB は外から来たファイルなので、次を満たさなければ開かない。

1. 一時ディレクトリへ複製し、その複製だけを触る
2. `PRAGMA trusted_schema = OFF`。`sqlite_master` にテーブルと索引以外（トリガー・ビュー）が
   あれば拒否する
3. `PRAGMA integrity_check` が `ok`
4. `_prisma_migrations` の適用済みの名前に、**アプリが持つ最新の migration より新しい未知の名前が無い**こと（起動時の判定と同じ。それより古い未知の名前は改名前の migration の記録として通す）。
   新しい未知の名前があれば「新しいアプリで書き出されています」と言って拒否する
5. 不足ぶんの migration を、アプリ起動時と同じ当て方（`migrationApplier.ts` の
   `applyMigrationSql`。起動時の `migrationDeployer` も同じ関数を使う）で当てる
6. 当てたあとの表と列が、アプリの DB と一致すること。`PRAGMA foreign_key_check` が空であること

## 5. 範囲の規則

### 5.1 実体の分け方

| 区分                     | 実体                                                                                                                 | 扱い                                                                                                      |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 根                       | `Exam` / `Coursework` / `Grade` / `AsbDefinition`                                                                    | 選ぶと、その子孫（カスケードで従う表）が丸ごと入る                                                        |
| 共通の実体               | `Student` / `Classroom` / `StudentClassroomMembership` / `SubtotalGroup` / `Subtotal` / `Tag` / `User`               | 入った行が参照するものを引き上げる。利用者が直接選ぶこともできる                                          |
| 中間テーブル             | `ExamTag` / `ExamClassroom` / `ExamSubtotalGroup` など                                                               | 根の側で入り、相手（共通の実体）を引き上げる                                                              |
| 両側が要る中間テーブル   | `CropSubtotal` / `TagSubtotalGroup`                                                                                  | 両側が入ったときだけ入る                                                                                  |
| 選べる（既定は含めない） | 利用者個人の設定5表（`UserKeyboardShortcut` ほか）、`AppPreference`、`AuditLog`、AI 採点の記録3表（`AiPrompt` ほか） | 関連データではない（AI 採点の記録は試験の配下だが実験の記録）。書き出し画面で選んだときだけ入れる（§5.5） |

`User` は「入った行が参照する人」だけを入れ、`passcode` は空にする。

### 5.2 根どうしの依存

成績算出を選ぶと、そのデータソース（`GradeDataSource`）が指すものを強制で含める。

- 試験（`examId`、`cropRegion` 経由の試験）
- 資料（`courseworkId`、`courseworkItem` 経由の資料）
- 小計（`subtotalId`）が属する小計グループ。**試験と `ExamSubtotalGroup` でつながっている
  とは限らない**ので、別に引き上げる

比較（`GradeComparison`）の比較先の成績算出も、既定で含める（外すことはできる。§5.3）。
比較先の成績算出も、そのデータソースが指す試験・資料を強制で含める。

この閉包は、増えなくなるまで回す。試験から解答用紙定義への外部キーは無いので、依存しない。

### 5.3 既定は全部、外すのは利用者の意向

既定では関連するデータを全て含める。在籍は、入った生徒の全期間の在籍とその学級を含める。
**在籍は常に全期間で、外す・絞る選択は設けない**（取り込み先に既にある在籍は残す（kept）だけなので、
多く含めても害が小さい）。
試験の採点・確定・返却版・メンバー（`UserExam`）・担当（`CropRegionAssignment`）は全員分を含める。

利用者が外せるものと、外したときに書き出されなくなるもの:

| 外せるもの                         | 外したときに書き出されないもの                                                                                              |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 比較先の成績算出                   | その成績算出を指す比較                                                                                                      |
| 他の教員の採点（本人分だけにする） | 他の教員の採点と注釈・確定（`ScoreDecision`）・返却版（`ReturnSnapshot`、他人の点を含むため）・他の教員のメンバーと担当の行 |
| 採点と答案（今の「雛形」）         | 受験生・採点・答案画像・確定・返却版                                                                                        |
| 個々の生徒・学級・タグ             | その実体を参照する行（受験・名簿・在籍・タグ付け）                                                                          |

外せないもの: 成績算出が使う試験・資料・小計グループ（§5.2）。選んだ根の配下（ページ・採点枠
など、根が成り立たなくなるもの）。

外した結果、外部キーが切れる行は書き出さない（§5.4 の検証を通る形にする）。外したことと件数は
画面と `manifest.json` に残す。

### 5.5 選べる項目（既定は含めない）

関連データではないが、選べば書き出せるもの。選んだかどうかも `manifest.json` に残す。

| 項目             | 選んだときに入る行                                                                                                                                                       | 取り込みでの扱い                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------- |
| 利用者個人の設定 | 書き出しに入った利用者の、設定5表の行                                                                                                                                    | 3択に従う。`(userId, キー)` の一意制約の衝突は §7.3   |
| 組織の設定       | `AppPreference` の全行                                                                                                                                                   | 3択に従う。`key` の一意制約の衝突は §7.3              |
| 監査ログ         | 範囲（`scopeId`）が書き出しに入った根を指す行と、その対象（`AuditLogTarget`）                                                                                            | 追記だけ（id で一致すれば何もしない）。書き換えない   |
| AI 採点の記録    | 書き出しに入った採点枠のプロンプト（`AiPrompt`）と、その実行（`AiGradingRun`）・判定（`AiGradingAttempt`）。判定は受験生に従い、本人分だけなら他の教員の実行と判定を外す | 3択に従う。「別で追加」では試験と一緒に id を振り直す |

### 5.4 書き出しの必須条件

書き出した DB で `PRAGMA foreign_key_check` が空であること。空でなければ書き出しを失敗させる
（規則の漏れなので、黙って行を落とさない）。`SetNull` の外部キー（招待者・割り当てた人・
確定者など）が範囲外を指すときは NULL にして書く。

```
sel = 利用者が選んだ根と共通の実体
繰り返し（増えなくなるまで）:
  成績算出のデータソースが指す試験・資料・小計グループを sel に足す
rows = sel の根の子孫
利用者が外したもの（§5.3）を除き、それを参照する行も除く
共通の実体を、rows が参照するものから引き上げる（在籍は全期間）
両側が要る中間テーブルを足す
User = rows が参照する利用者（passcode は空）
SetNull の外部キーで範囲外を指すものは NULL
検証: foreign_key_check が空
```

## 6. 書き出し画面

- **入口は今の各画面のボタンのまま**、開くダイアログを1つにする。押した画面の実体が最初から
  チェックされた状態で開く
- 4種と共通の実体を、種ごとの一覧で選ぶ。件数の増える一覧は共通の Combobox（検索・番号・カナで
  絞れる）に揃える
- 選んだ実体ごとに、**関連して含まれるもの**を既定でチェック済みの形で並べる（例: 成績算出の下に
  使う試験・資料・比較先の成績算出、試験の下に受験生・採点・答案・在籍）
- 成績算出が強制で含める試験・資料・小計グループは、チェック済みで外せない表示にし、
  「成績算出『…』が使うため」と理由を添える
- **関連するものを外すと、その行を「含めないもの」として目立つ色で残し、外したことで書き出されなく
  なるもの（§5.3 の表の右列）を件数つきで示す。** 画面の下に「含めないもの」の一覧を常に出し、
  何も外していなければ「関連するデータを全て含めます」と出す
- 関連データの外に、選べる項目（§5.5）を既定で外した状態で並べる。こちらは「含めないもの」の
  一覧には出さない（本来関連するものではないため）
- 書き出す前に、表ごとの行数と、欠けている画像と、「含めないもの」の一覧を示す
- 結果は共通の `ExportResultSummary` で示す（欠けた画像・失敗）

## 7. 取り込み

### 7.1 流れ

1. **開く**: §4.1 の守りを通し、アーカイブの DB を現行化する。現行化の前後で各表の id の集合を
   比べ、**現行化で生まれた行**を控える（§7.3 で使う）。`manifest.json` に「外したもの」があれば、
   「このアーカイブには〇〇が含まれていません」と示す。取り込みは既存の行を消さないので、
   含まれていないものは取り込み先でそのまま残る
2. **方針を選ぶ**: 3択を1回だけ選ぶ（`ImportActionChoice` を使う）
3. **紐づけ（付加機能）**: id で一致しなかった共通の実体（生徒・学級・小計グループ・利用者）
   だけを、今と同じ照合（学籍番号・名前）で候補に出し、「同じもの / 新規 / 取り込まない」を
   選ぶ。今ある紐づけの部品（`IdIntegrationStep` と各 matcher）を使う
4. **一意制約の衝突**: §7.3
5. **確認**: 表ごとの新規・更新・変更なしの件数、§7.3 の衝突、成績算出への影響（§7.5）
6. **実行**: 1本のトランザクションで書く。画像はコミット後にコピーする（§7.4）

既存の利用者の `passcode` は書き換えない（アーカイブ側は空にして書き出している。§5.1）。

### 7.2 行の書き方

- **表ごとの手書きの処理（`process*`）をやめ、スキーマから回す汎用の書き込みにする。** 外部キーの
  順（親が先）に表を回し、各行を id で照合して、3択に従って作る・置き換える・残す
- 値の扱いは `importValuePolicy` をそのまま使う。時刻の扱いも同じ（上書きは取り込み時刻、統合は
  元の時刻）
- 「別で追加」は、**根の子孫の id をすべて振り直す**（外部キーのグラフから範囲を導く）。共通の
  実体は振り直さず、既存に触らず足りないものだけ足す（今と同じ）
  - 振り直すのは、根の行と、参照先のどれかが振り直される従属・中間テーブルの行。共通の実体の配下
    （生徒の在籍、小計グループの小計など）は振り直さない（同じ在籍が2行になるため）
  - 外部キーでない列に埋め込まれた id は、名指しの一覧（`archiveEmbeddedIds.ts`。今は
    `ReturnSnapshot.scoresJson` だけ）を、JSON の文字列の値の完全一致で書き換える。uuid の形を
    全文から拾って置き換えることはしない（無関係な文字列まで化けうる）。監査ログは追記だけなので
    元の id を指したまま残す
- 利用者の `passcode` / `passcodeType` は置き換えない（§7.1）。監査ログは3択に関わらず追記だけ
  （§5.5）で、新しく作るときも時刻はアーカイブのまま

### 7.3 一意制約の衝突

id で一致しなかった行を書く前に、その表の `@@unique`（と1列の `@unique`）の値で既存の行を引く。
当たれば衝突として扱う。

| 方針     | 値                         | 採用する id                                              |
| -------- | -------------------------- | -------------------------------------------------------- |
| 上書き   | アーカイブの値で置き換える | 利用者が選ぶ                                             |
| 統合     | 新しい方が勝つ（LWW）      | 利用者が選ぶ                                             |
| 別で追加 | 既存に触らない             | 既存の id で固定。アーカイブ側の子は既存の行へ付け替える |

- id の選択は一括で選べ、1件ずつも変えられる。一括の初期値は「取り込み先の id」
  （取り込み先の id は、同期している他の端末で既に使われている可能性があるため）
- アーカイブ側の id を採るときは、取り込み先の行の id を付け替え、その行を参照する子の外部キーを
  `UPDATE` で付け替える。削除して作り直す方式は使わない（カスケードで子を失う）
- **現行化で生まれた行**（§7.1 の1）が衝突したときは、「このアーカイブは古い版で作られたため、
  〇〇は版をまたいで同じものかを id で判断できません」と理由を添えて示す。統合のときの LWW は、
  その行の `updatedAt`（現行化した時刻）ではなく `manifest.exportedAt` で比べる
- `@@unique` の無い表は衝突を検知できない。§8 の規約で、migration がそうした表に行を作らない
  ようにする

**決めて、書く**: 衝突は親の付け替えの結果として子に連鎖して生まれる（受験生を既存の id に寄せると、
アーカイブの確定（`ScoreDecision`）が既存の確定と `(cropRegionId, examStudentId)` でぶつかる）。
そこで全体を先に計画せず、1本のトランザクションの中で、表を外部キーの親が先の順に1表ずつ
「決めて、書く」。各表では、前の表までで決まった id の写しで参照を書き換え、照合の決定（§7.1 の3）を
当て、id で引いて3択で決め、**今の取り込み先の状態**（同じトランザクションで書いた・付け替えた
結果を含む）に対して衝突を検知して解いてから書く。付け替えの途中は親子が一時的にずれるので、
外部キーの検査はコミットまで遅らせる（`PRAGMA defer_foreign_keys = ON`）。

照合で「同じもの・アーカイブの id」を選ぶのも、同じ付け替えで行う（§9）。ただし「別で追加」では
既存の行に触らないので、付け替えを求める照合の決定があれば止める。

**解けない衝突**は、何も書かずに止め、理由を返す:

| 種類                  | 意味                                                                      |
| --------------------- | ------------------------------------------------------------------------- |
| `multipleExisting`    | 1行が複数の既存行とぶつかる                                               |
| `sharedExisting`      | 複数のアーカイブ行が同じ既存行に寄る（id の一致・照合・衝突の解決を含む） |
| `replacementCollides` | id が一致した行の置き換えが、別の既存行とぶつかる（選べる id が無い）     |
| `duplicateInArchive`  | 参照を書き換えた結果、アーカイブの複数の行が同じ一意キーになる            |
| `idTaken`             | 付け替え先のアーカイブの id が、取り込み先に既にある                      |
| `matchTargetMissing`  | 照合で選んだ既存の行が、取り込み先に無い                                  |
| `renameInSeparate`    | 別で追加なのに、既存の行をアーカイブの id へ付け替える照合の決定がある    |

確認画面の数字は、同じ処理を実際に書いてからロールバックする試し取り込みで出す（本番と同じ計算）。

### 7.4 画像

- `files/` を、DB の相対パスのままデータディレクトリへ写す
- 写すのは、行の取り込みで作った・置き換えた行が指すファイルだけ。取り込まなかった行や、既存へ
  寄せて書かなかった行のファイルは写さない（どの行からも参照されず孤立する）
- 作った・置き換えた行のファイルは、上書きのときだけ既存のファイルも置き換える（今の試験の
  取り込みは置き換えない。§3.3）
- 書かずに残した行のファイルは、取り込み先の行も同じパスを指していて、取り込み先にファイルが
  無いときだけ写す（行は同じだが画像が欠けている端末を直す）。既にあるものは置き換えない
- パスに id が区切りとして入る表（試験・解答用紙定義）は一意制約を持たず照合の対象でもないので、
  付け替えでパスが変わることはない（規約テストで縛る）
- 「別で追加」で根の id を振り直したときは、パスに含まれる id も書き換える
- 模範解答の置き場が2系統ある件（§3.2）は、どちらのパスもそのまま受け付ける

### 7.5 成績算出への影響（#1308）

確認の段に、「この取り込みで値が変わる成績算出と評価項目」を示す。

- main は、取り込み先の既存の行と、アーカイブ側の該当する行を、加工せずに返す
- renderer が差分を取り、成績算出の詳細に同梱された「使っているデータソース」の include
  （`gradeDataSourceUsage.ts`）と、その導出関数（`gradeReferenceMessages.ts`）で、影響する評価項目へ
  写す。確定済みの評価項目では文言を強める（`gradeLock.ts` の `frozenNote`）
- 判定の粒度は「値が実際に変わりそうな評価項目だけ」。関与しているだけで出すと、統合のたびに
  警告が出て慣れてしまう

**実装**（段階5b）: 材料は試し取り込み（`unifiedArchive:analyze`）の戻り値に同梱する。別の
チャンネルにしないのは、取り込み後の状態が試し取り込みのトランザクションの中にしか無いため。

- `gradeInputChanges`: 成績算出が読む表（`GRADE_CALCULATION_TABLES`）の、作る・置き換える行の
  書く前（作る行は null）と書いた後。どちらも取り込み先から同じ方法で引いた生の行
  （`archiveGradeInputChanges.ts`）。残す行・取り込まない行は載せない。本番の取り込みでは集めない
- `gradeImpactSource`: 書いた行の外部キーを登録表の references で1段ずつ辿った親の行（成績算出が
  読む表の中だけ）と、そこに現れた試験・資料・小計・評価項目・生徒・学級を、使われ方の include
  （`gradeDataSourceUsage.ts`）を同梱して（`archiveGradeImpactSource.ts`）
- 差分と写し方は renderer（`archiveGradeInputDiff.ts`・`archiveGradeImpact.ts`）。時刻と、値に
  使わない列（名前・並び順・用紙上の位置・コメント・誰がいつ確定したか。表ごとに名指し）だけの
  違いは「変わらない」。採点・受験生は試験を使うデータソースへ（設問を指すものはその設問の採点
  だけ、生徒1人の行はその生徒が名簿に載る成績算出だけ）、構成は `cropRegionUsages` などの導出で、
  資料は項目・資料を使うデータソースへ、成績算出の中の行は評価項目へ、名簿の行・生徒・在籍・
  学級は成績算出の名簿の変化として。取り込みで新しく作られる成績算出は出さない

## 8. migration に課す規約

アーカイブの DB にも、アプリと同じ migration を当てる。一部だけの DB でも、全体の DB と同じ
結果になるよう、今後の migration は次を守る。

1. **既存の行の id と時刻を変えない**
2. **他の行を参照するのは、範囲の内側（同じ試験・成績算出・資料・利用者の中）だけ。** 集約や
   重複削除の `GROUP BY` / `PARTITION BY` には範囲の親キーを含める
3. **参照先が無いときは元の値を保つ。** `INNER JOIN` で行を落とすことや、存在しないことを理由に
   NULL にしたり消したりすることを、migration に書かない
4. **既存のデータから新しい行を作ってよいのは、`@@unique`（または1列の `@unique`）を持つ表だけ。**
   新しい行の id は乱数でよい（衝突は §7.3 で拾う）

2026-10-04 の試作で、実データの途中版の DB（6/13 時点と 7/31 時点）から「試験1件」と「成績算出と、
それが使う試験・資料」を切り出し、全体と一部の両方に migration を1本ずつ当てて突き合わせた
（56本と22本）。**一部だけの DB による欠落・値の違いは0件**で、ずれたのは乱数の id を振る3本が
新しく作った行の id と `updatedAt` だけだった。既存の行の時刻は保たれていた。この試作を回帰
テストにして、上の規約を機械で検査する（§10 の段階1）。

## 0. 出発点: 扱いたい運用が2つある

|                          | **A: 入試型**                        | **B: 学年運用型**                                   |
| ------------------------ | ------------------------------------ | --------------------------------------------------- |
| 例                       | 入学試験の採点                       | 学年2クラスを2人の教員で担当し、1つの試験として扱う |
| 何で割るか               | **設問**で割る                       | **生徒（学級）**で割る                              |
| 同じ答案を複数人が見るか | **見る**（独立採点・ダブルチェック） | 見ない（担当が排他）                                |
| 突合・確定               | **必要**（#840 の本体）              | 不要（担当が排他なので競合が起きない）              |
| 匿名性                   | **必須**（採点者バイアスの低減）     | 不要（自分の学級なので誰か分かってよい）            |
| 権限の形                 | OWNER 1人（裁定者）＋ GRADER n人     | **OWNER 2人**（対等な運用者）                       |
| #840 で扱えるか          | **扱える**                           | **扱えない**（生徒側の分割手段が無い）              |

**両方を1つの仕組みで扱う**のが本設計の目的。

## 1. 調査で判明した事実

### 1-1. 07 に学級の概念が一切ない

`src/components/exams/07-score-at-once/` 配下に `classroom` の参照が **0件**。
採点画面は学級を知らないため、B の教員が自分の学級だけ採点するには
**氏名を目視で拾う**しかなく、匿名採点と正面から衝突する。

### 1-2. 段階アクセスの制御点は1箇所に集約されている

| 要素                                       | 場所                                  |
| ------------------------------------------ | ------------------------------------- |
| 全8段階の定義（`workflowSteps`）とパンくず | `src/app/exams/[examId]/layout.tsx`   |
| 唯一の共通レイアウト                       | 同上（`/exams/[examId]/` 直下に1つ）  |
| メンバー管理ダイアログの起動               | 同 `:107`（`MemberInviteDialog`）     |
| 07 → 06 への「戻る」ボタン                 | 同 `:118`（条件付き表示が必要になる） |

`GuardedLink`（`src/components/common/GuardedLink.tsx`）は**未保存変更のナビゲーションガード**であり、
権限とは無関係。**権限ガードは現状どこにも存在しない。**

### 1-3. 「OWNER として追加」する操作が存在しない

| 関数                                | 実際の挙動                                                                |
| ----------------------------------- | ------------------------------------------------------------------------- |
| `setExamOwner`（`userExam.ts:101`） | UserExam 行を新規作成するだけ。試験作成時専用                             |
| `transferOwnership`（`:239`）       | **移譲**。現 OWNER を GRADER に降格し対象を昇格。OWNER は常に1人          |
| `removeExamMember`（`:205`）        | `role === "OWNER"` の行は**誰も削除できない**（昇格が一方通行の罠になる） |

B（OWNER 2人）を成立させるには**昇格・降格の新設が前提**。

### 1-4. アーカイブを越えるもの／越えないもの

| テーブル      | アーカイブ                                                                                           | 帰結                                            |
| ------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `UserExam`    | **越えない**（`dataCollector.ts:532` で `userExams: []`、import は現ユーザーを OWNER として1件作成） | ここに列を足してもアーカイブ改版が不要          |
| `ExamStudent` | **越える**                                                                                           | ここに紐づく新テーブルは **archive 改版が必要** |

## 2. 中心原則

### 2-1. 採点セルの同定は常に `Student × CropRegion`

学級は「どの生徒を選ぶか」の**道具**であって、担当や採点結果の**鍵にはしない**。

理由は3つ。

1. **学級に属さない生徒がいる。** 学級を鍵にすると、各教員が絞り込んだ瞬間その生徒はどの画面にも現れず、
   誰も採点しないまま未採点として出力される
2. **所属は期間で変わる。** `StudentClassroomMembership` に `startDate` / `endDate` があり、1人が複数所属を持ちうる。
   学級を鍵にすると「どの時点のどの所属か」で担当が揺れる
3. 既存規約（同定は必ず id、序数や名前を鍵にしない）と一致する

「この試験でこの生徒はどの学級か」の解決は既存の仕組み（受験日基準の `getClassroomMembersForExam`、
renderer 側の採番学級解決）を使い、新設しない。

### 2-2. 絞り込みは「役割」ではなく「自分の割り当て」で決まる

OWNER の特権は **割り当てを変更できること**であって、**絞り込みを無視することではない**。

### 2-3. 担当0人は全員担当（両軸で鏡になる）

| 軸   | 規則                        |
| ---- | --------------------------- |
| 設問 | 担当0人の設問は全員担当     |
| 生徒 | **担当0人の生徒は全員担当** |

この鏡像により、**学級未所属の生徒が消える問題が自動的に解ける**。
学級から一括割り当てしても、学級に属さない生徒は担当0人のまま＝全員に見える。

### 2-4. これは権限境界ではない

ローカルインストール＋NAS 共有で、GRADER の手元に DB ファイルそのものがある。
URL 直打ちや DB 直読みは止められない。

得られるのは「**採点者の作業導線から採点以外を外す**」であって「見せない」ではない。
UI 文言もこの範囲で書く。「アクセスを禁止します」は過剰約束。

それでも十分と判断する。目的は不正防止ではなく
(a) 採点者が誤って準備段階の設定を壊さない、(b) 名簿・答案画面を経由しないので匿名採点が成立する、の2点だから。

## 3. 設計判断

### 3-1. 担当割当は2軸を対等にする

07 のグリッドは「選択中の設問 × 生徒」なので、2つの割り当ては直交する。

| 軸   | テーブル                | 何を絞るか         | 状態                 |
| ---- | ----------------------- | ------------------ | -------------------- |
| 設問 | `CropRegionAssignment`  | 選択できる設問     | **実装済み**（#840） |
| 生徒 | `ExamStudentAssignment` | グリッドに出る生徒 | 新規                 |

```prisma
/// 生徒ごとの採点担当。設問側の CropRegionAssignment と対等な軸。
/// idは uuidv5(examStudentId + userId) で決定論的に生成する（同期での unique 衝突回避）。
model ExamStudentAssignment {
  id            String      @id
  examStudentId String
  userId        String
  assignedBy    String?
  createdAt     DateTime    @default(now())
  updatedAt     DateTime    @default(now()) @updatedAt
  examStudent   ExamStudent @relation(fields: [examStudentId], references: [id], onDelete: Cascade, onUpdate: NoAction)
  user          User        @relation(fields: [userId], references: [id], onDelete: Cascade, onUpdate: NoAction)
  assigner      User?       @relation("StudentAssignedByUser", fields: [assignedBy], references: [id], onDelete: SetNull, onUpdate: NoAction)

  @@unique([examStudentId, userId])
  @@index([userId])
}
```

- 鍵・id生成・同期の性質を `CropRegionAssignment` と揃える
- `ExamStudent`（試験スコープの生徒行）に紐づける。`Student` ではなく `ExamStudent` にするのは
  試験ごとに担当が変わるため。#962（セル層の ExamStudent 化）が進む場合も同じ層にあるので矛盾しない
- **見えるセル = 自分の設問 × 自分の生徒**（AND）

**学級からの一括割り当て**は UI 操作として提供する。
「学級を選ぶ → その時点の所属生徒を担当として焼き込む」。`customOrder` の実体化と同じパターン。
焼き込んだ後は生徒単位の割当行なので、後から所属が変わっても担当は揺れない。

#### 06（生徒答案）も同じ規則で絞る

生徒割り当ては 07 だけでなく **06 にも効かせる**。パターンBで各教員が自分の学級の答案を
アップロードする場面がそのまま成立する。

06 は OWNER しか入れない（3-3）ので、対象は常に OWNER。したがって **2-2 の原則がそのまま適用される** —
役割で素通りさせず、**自分の割り当てで絞り、手動で「すべて表示」に切り替えられる**。

未割り当ての生徒の答案を扱えなくなる懸念は、2-3 の「担当0人の生徒は全員担当」で解消する。
誰にも割り当てられていない生徒は常に全員に見えるので、絞り込みで消えることはない。

### 3-2. 【#840 の訂正】OWNER の絞り込みバイパスを撤回する

**実装済みの以下は誤り。**

```ts
// src/components/exams/07-score-at-once/ScoringMain/hooks/useAssignedCropRegions.ts:52
if (assignments.length === 0 || canManage || !userId) return cropRegions
//                               ^^^^^^^^^ OWNER なら絞り込みを丸ごと素通り
```

パターンBでは両者 OWNER なので、これでは割り当てても2人とも全生徒・全設問が見えてしまい、
**割り当てが無意味になる**。

|                | 誤（実装済み）             | 正                                                 |
| -------------- | -------------------------- | -------------------------------------------------- |
| 絞り込みの根拠 | **役割**（OWNER なら無視） | **自分の割り当て**（役割は無関係）                 |
| OWNER の特権   | 全部見える                 | **割り当てを変更できる**（自分への割り当てを含む） |
| 全部見たいとき | 自動でバイパス             | **手動で「すべて表示」に切り替える**               |

裁定のために全設問を見たいケースは実在するが、自動バイパスではなく明示トグルであるべき。
確定パネル自体は割り当てと無関係に全競合を出すので影響を受けない。

あわせて `electron-src/lib/prisma/cropRegionAssignment.ts` の冒頭コメントを訂正する（「OWNER は担当に関係なく
全設問を選択可」という #840 当時の前提が書かれている）。

**自分への割り当ては既に可能**（`assignCropRegion` は割当先を `UserExam` メンバーに限り OWNER もメンバー、
`QuestionAssignmentRow` のプルダウンも `members` をそのまま出す）。ここは変更不要。

### 3-3. 段階アクセスは「2ロール＋昇格/降格」＋ 08 のみ OWNER が個別に許可できる

**GRADER は 07 のみ。準備段階（01-06）をさせたいなら OWNER に昇格する。**

段階ごとのスイッチを**全段階に対して**作る案（`UserExam` に Boolean 3本等）とは比べた結果、採らない:

|              | 全段階のスイッチ               | **2ロール＋昇格/降格**              |
| ------------ | ------------------------------ | ----------------------------------- |
| スキーマ変更 | `UserExam` に Boolean 3本      | `role` は既に String 列（変更なし） |
| 概念         | 「誰にどの段階を許すか」の行列 | **ロール2つだけ**                   |

意味論が綺麗になる。**匿名採点を壊すのは 05・06・08 だけ**（01-04 は答案と生徒の対応を見せない）。
「答案スキャンを手伝ってほしい ＝ その人は名前を見る ＝ その試験でその人に匿名性は無い ＝ OWNER でよい」
が自然に繋がる。中間ロールを作るとこの線引きがぼやける。

#### 08（結果出力）だけは例外。OWNER がメンバーごとに許可する

01-06 と 08 は性質が違う。

- **01-06 は試験の構造・名簿を編集する**。ここを GRADER に開くのは「昇格」と同じ意味になる
- **08 は自分の採点結果を読むだけ**。編集ではない

GRADER が自分の採点結果を一切確認できないのは実運用で無理があるため、**08 のみ OWNER が
メンバーごとに許可できる**ようにする。

```prisma
model UserExam {
  // ...
  /// 結果出力（08）へのアクセスを許可するか。OWNER は常に可。
  /// 01-06 に相当するスイッチは持たない（そこを開けたいなら OWNER に昇格する）
  canExportResults Boolean @default(false)
}
```

- **`UserExam` に持つ**理由: メンバーごとに決められ、かつ**アーカイブを越えないので改版が不要**（→ 1-4）
- 既定は `false`（GRADER は 07 のみ）。OWNER が明示的に開ける
- OWNER は `role` で判定するのでこのフラグに影響されない

#### 匿名採点との衝突は「止めずに伝える」

匿名採点が有効な試験で GRADER に 08 を許可すると、**出力結果から氏名と得点の対応が読めてしまう**ので
匿名性は実質的に無効になる。

ただし**禁止はしない**。#840 で確立した方針（判断者の裁量を妨げず、設計努力は「止める」ではなく
「伝える」に振る）と同じく、OWNER が許可しようとしたときに
「匿名採点を有効にしていますが、出力を許可すると採点者は氏名と得点の対応を見られます」と明示する。

これに伴い必要な変更:

- **昇格・降格の操作を新設**（現状 `transferOwnership` は移譲しかできない）
- `removeExamMember` の「OWNER は削除不可」を「**最後の1人の OWNER は削除・降格できない**」に変更
- `layout.tsx` で**ナビからの除去とルートガードの両方**を行う（リンクを隠すだけでは足りない）
- `layout.tsx:118` の 07 → 06「戻る」ボタンを条件付きに
- メンバー管理ダイアログに**昇格/降格**と**08 の許可トグル**を足す

### 3-4. 複数 OWNER と「確定」

`canDecideScore` は「OWNER なら誰でも可」なので、OWNER が2人以上いると同じセルを両者が確定でき後勝ち（LWW）になる。

**それでよい。** OWNER は裁定者として選ばれた人であり、複数いれば合議に近い。
確定パネルは確定者名と日時を表示し、`exam.score.decide` の監査ログも残るので誰が何を上書きしたかは追える。

なおパターンBでは担当生徒が排他なので競合自体が起きず、この論点は顕在化しない。

#840 の実装は「試験OWNERによる裁定」を単数前提で組んでいるため、複数OWNERを許すなら見直しが要る。

### 3-5. 匿名採点（#839）は OWNER が試験単位で固定できる

**機能として持つ**（競合対策としての位置づけ）。作りは表示制御に留めるが、
**採点者が自分で解除できてはバイアス低減にならない**ので、OWNER が試験単位で固定できるようにする。

```prisma
model Exam {
  // ...
  /// 匿名採点を強制するか。ONの間、GRADER は 07 で生徒識別情報を表示できない
  anonymousScoringEnforced Boolean @default(false)
}
```

**二層構造**にする。

| 層         | 保存先                            | 誰が操作するか | 効果                                                  |
| ---------- | --------------------------------- | -------------- | ----------------------------------------------------- |
| 試験の強制 | `Exam.anonymousScoringEnforced`   | **OWNER のみ** | ON の間、GRADER のトグルは無効（理由を表示）          |
| 個人の任意 | `UserPreference.anonymousScoring` | 各自           | 強制が OFF のときだけ有効。単独利用者が自主的に隠す用 |

有効判定は**論理和**（どちらかが ON なら隠す）。強制が ON のとき GRADER 側のトグルは
disabled にし、「この試験では匿名採点が有効です」と表示する。

- 当初「スキーマ変更のコストに見合わない」として見送ったが、**3-1 で migration と archive 改版を
  行うため `Exam` への列追加コストはほぼゼロ**になる
- OWNER 自身は匿名の対象外。裁定（確定パネル）で生徒名が必要なため
- `showStudentNames`（UserPreference、デフォルト `true`）を **`anonymousScoring`（デフォルト `false`）に一本化**。
  「名前ラベルだけ隠すが画像の氏名欄は出す」中間状態に実用的意味がなく、2キー並存は必ず片方の漏れを生む。
  移行は「旧キーが `false` なら新キー `true` として読む」フォールバック1回
- **「採点完了後に自動解除」は実装しない。** 勝手に匿名が解けるのは事故のもと

現状の実効範囲と漏れ経路:

| 箇所                                                  | 内容                                                  | 状態                   |
| ----------------------------------------------------- | ----------------------------------------------------- | ---------------------- |
| `ScoringGrid/GridCell.tsx:146,155`                    | セル下の氏名ラベル                                    | 対応済                 |
| `ScoringGrid/GridCell.tsx:127`                        | `alt="○○の答案"`                                      | 未対応                 |
| `ScoringIndividual/StudentAnswerPanel.tsx:80,87`      | 生徒セレクト（氏名＋出席番号）                        | 未対応                 |
| `ScoringSidePanel/AnnotationBrowserPanel.tsx:333,481` | 生徒一覧                                              | 未対応                 |
| **答案画像の氏名欄（`STUDENT_NAME` 領域のマスク）**   | ページ全体描画・`expandMargin` 拡張時に写る           | **未対応・ここが本体** |
| 並び順                                                | `customOrder`（出席番号順）のままだと順序で推測できる | 未対応                 |

実装ポイント:

- 採点画面は `getQuestionAnswerRegionsByExamId`（`cropRegion.ts:231`）で **QUESTION_ANSWER 型しかロードしていない**ため、
  `STUDENT_NAME` / `STUDENT_ID` 領域を `getCropRegionsByExamId` で追加取得する
- 画像マスクの差し込みは2箇所:
  - 個別表示: `ScoringIndividual/hooks/core/useCanvasDrawing.ts:267` の `ctx.drawImage` 直後
  - グリッド: `ScoringMain/CroppedAnswerImage.tsx` の可視矩形と交差するときだけ塗る
- 匿名モード中は `studentAnswerImage.id`（uuid）順に並べる。名簿と無関係かつ再読込しても安定

## 5. 決着した論点

当初の未決3点は、いずれも**固定の仕様にせず OWNER の操作対象にする**ことで決着した。
「アプリが決める」のではなく「試験の運営者が決める」に寄せる方針。

| 旧・未決                        | 結論                                                                     | 保存先                          | 操作者            |
| ------------------------------- | ------------------------------------------------------------------------ | ------------------------------- | ----------------- |

### 残る確認事項

設計上の未決はないが、実装時に判断が要る点:

- **匿名採点の強制と「すべて表示」トグルの関係。** 強制 ON の GRADER には
  06/07 の「すべて表示」も出さないのが自然か（そもそも 06 に入れないので 07 のみの論点）
- **`UserExam.canExportResults` の既定値。** 本書では `false`（07 のみ）としたが、
  既存試験の GRADER が突然 08 を失うことになる。移行時のみ `true` で作る選択肢もある

## 6. 実装上の罠

- **リンクを隠すだけでは足りない。** `layout.tsx` でルート自体をガードし、許可外なら 07 へリダイレクト＋理由表示
- **昇格を一方通行にしない。** `removeExamMember` の「OWNER は削除不可」を先に直さないと、
  一度昇格した人を戻せなくなる
- **学級を担当の鍵にしない**（2-1）。一括割り当ては必ず生徒行へ焼き込む
- **担当0人＝全員担当の鏡像規則**（2-3）を両軸に必ず入れる。片方だけだと生徒か設問が消える
- `ExamStudentAssignment`（`ExamStudent` 紐づき）と `Exam.anonymousScoringEnforced` は
  **どちらもアーカイブを越える**。archive 1.21.0 ＋ トランスフォーマー ＋ **新規/merge の両インポート経路**の
  対応が必要（#840 で 1.20.0 を通した手順がそのまま使える。merge 経路の対応漏れは #840 のレビューで
  実際に指摘された）
- `UserExam.canExportResults` は**アーカイブを越えない**（`userExams: []`）。
  インポート後は既定値になるので、移行先で付け直す必要があることを警告で伝える
- **匿名採点の強制と 08 の許可は衝突する。** 止めずに警告する（3-3）
- 同期は `sqlite-nas-sync` が自動検出するので `syncTableConfig.ts` への登録は不要（除外リスト方式）
- 新テーブル追加で `normalizeDatetime.test.ts` の `POST_MIGRATION_TABLES` に追記が必要

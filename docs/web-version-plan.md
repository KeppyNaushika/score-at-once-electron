# web 版 — 仕組みと公開までの作業

**2026-10-12 時点（#1464 まで入った）。** web 版の組み立て方と、公開までに残っている作業を置く。
済んだ作業は消し、組み立て方の節へ畳む。経緯は issue とコミットに残る（#1443 静的書き出し、
#1449 main の fs の非同期化、#1464 web 版の組み立てと採点の流れ）。

**次に着手するのは「公開までの作業」の 3（公開前のセキュリティ点検）。**

## 原則

| 原則                                 | 帰結                                                                                                   |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| **ホストは機微データを保存しない**   | データはブラウザの OPFS にだけ置く。ホストは静的ファイルを配るだけで、サーバー側の処理も DB も持たない |
| **デスクトップ版とソースを共有する** | main の処理を書き換えずにブラウザで動かす。差し替えるのは Node / Electron 専用のモジュールだけ         |
| **ソースはすべて公開する**           | web 版だけの非公開部分を作らない                                                                       |

web 版は**1人用**。端末をまたいでデータを移すのは統合アーカイブ（`.sao`）で、
複数の教員で同じデータを採点するのはデスクトップ版の共有モードの役目。

## 組み立て方（済んでいるもの）

```
画面（renderer/ の静的書き出し）
  └ web/page/        preload.ts を無改変で束ね、electron だけ差し替え
        │ postMessage（型は web/ipcProtocol.ts）
        ▼
Worker（web/worker/）
  └ setupAllIPCHandlers() を無改変で実行
  └ Prisma（runtime = "workerd" で generated/prisma-web へ生成）
  └ better-sqlite3 の形に包んだ sqlite-wasm（opfs-sahpool）
  └ 画像処理は wasm-vips（imageOps.ts の窓口ごと差し替え）
Service Worker（web/serviceWorker/）
  └ /__appimg/<相対パス> を OPFS の data/ から返す
```

- **画面:** デスクトップ版と同じ `renderer/` を配る。動的ルートは殻（param `__`）を
  1枚だけ書き出し、実 id の URL は `src/lib/routeShell.ts` の `toRouteShellPath` で
  殻へ読み替える。この規則の出どころはここだけ。
- **DB:** 包み（`web/worker/betterSqlite3Shim.ts`）の上で、本物の
  `@prisma/adapter-better-sqlite3` を動かす。おかげで成績ロックの関所
  （`sqliteConnection.ts`）、初期スキーマと migration の適用、初期データの投入が
  デスクトップ版と同じコードを通る。新規 DB の `_prisma_migrations` は、名前と checksum
  までデスクトップ版と一致する。
- **ファイル:** `fs/promises` を OPFS の実ファイル階層で差し替える（仮想パス
  `/opfs/<rest>` ↔ OPFS 直下の `<rest>`）。メモリには持たない。`open` の FileHandle は、
  読みは `File.slice`、書きは `createSyncAccessHandle`（`web/worker/opfsFileHandle.ts`）。
  - 画面で選んだファイルは `File` のまま Worker へ渡し、仮想パスに結び付ける。
  - 保存ダイアログの先へ書いたファイルは、OPFS の置き場に書いて閉じた時点で、`File` のまま
    ダウンロードとして画面へ渡す（写さない。置き場は10分後と次の起動時に消す）。
- **1タブ制御:** opfs-sahpool はファイルを1タブで専有するので、Worker を起動する前に
  Web Locks を取る。2つ目のタブでは起動しない。
- **画像処理:** `electron-src/lib/imageOps.ts` の窓口ごと `web/worker/imageOpsVips.ts`
  （wasm-vips）に差し替える。sharp の処理の段を同じ順・同じ引数で写してあり、全関数で
  sharp と出力が一致することを `__tests__/web/imageOpsVipsParity.test.ts` が縛る。
  wasm-vips は COOP/COEP を要し、最初に画像を扱うときに読む。デスクトップ版は sharp のまま。
- **`.sao`:** zip は自作の読み書き（`archiveZipWriter.ts` / `archiveZipReader.ts`、圧縮だけ fflate）。
  FileHandle で位置を指定して読み書きするのでファイル全体をメモリに載せず、4GB を超えるものは
  ZIP64 で書く（2GiB 超の取り込みも通る）。中の SQLite はファイルとして開かず中身をメモリで
  扱う（`archiveDatabaseImage.ts`）。デスクトップ版も同じコードで、archiver は外した。書き出しの作業者は、デスクトップ版は utilityProcess、
  web 版は同じ Worker の中で走らせる（DB は1つの Worker しか開けない）。旧形式5種は
  web では選んだ時点で断り、デスクトップ版で `.sao` にしてから持ち込んでもらう。
- **開くダイアログ:** Worker の `dialog.showOpenDialog` が画面に選択を頼み、画面が
  `<input type="file">` を出す。ユーザー操作の有効期間が切れていたら案内のボタンで選ばせる。
  フォルダは選ばせない（フォルダを選ぶ経路はどれも書き出し先を決めるもので、保存の領域を返す）。
- **印刷と PDF:** オフスクリーンのウィンドウの代わりに、画面の見えない `iframe` で
  `print()` する（ベクタのまま）。PDF のファイルは印刷ダイアログの「PDF に保存」に任せる。
  窓口は `electron-src/lib/printUtils.ts` で、web では `web/worker/htmlPrinting.ts` に差し替える。
- **差し替え:** モジュール名の差し替えと、ファイル単位の差し替え（`imageOps.ts`・`printUtils.ts`）は
  `scripts/web/buildWorker.mjs` の表にまとめてある。
- **web で出さない機能:** 押してから失敗させず、画面で出し分ける（描画では `useIsWebRuntime`、
  イベントの中では `isWebRuntime`）。
  - 同期設定のタブ（共有モード・共有フォルダ・データフォルダの設定・同期）と、その使い方ガイドは
    出さない。web 版は1人用で、共有はデスクトップ版の役目。
  - 「消灯時に自動フルスクリーン」は出さない（ブラウザの全画面は利用者の操作が要り、無操作で
    消灯するときには入れない）。
  - プロジェクターモードは、画面消灯の抑止をブラウザの Screen Wake Lock で行う
    （`src/hooks/useScreenWakeLock.ts`。ページが見えている間だけ効く）。オン・オフはデスクトップ版と
    同じくアプリを開いている間だけ覚えるので、再読み込みするとオフに戻る。
  - AI 採点はサイドバーに出さず、`/ai-grading` を直に開くと使えない理由を出す（出すかは「判断待ち」）。
  - 一覧の「読み込み」は `.sao` だけを受け付け、旧形式5種と外部形式（`.hsz`・`.dat`）は選んだ
    時点で断る。使い方ガイドも web では「デスクトップ版で `.sao` にしてから」と案内する。
- **web かどうか:** ビルドではなく実行時に、入口が立てる大域の `scoreAtOnceWeb` で
  見分ける（画面と Worker の両方で立てる）。使っているのは画像 URL の規則
  （`src/lib/appImageUrl.ts`）と `.sao` の書き出しの作業者の起こし方。

手元で試す:

```bash
npx next build && npm run web:build && npm run web:serve   # http://127.0.0.1:4173
```

## 公開までの作業

上ほど先にやる。採点の流れ（取り込み → 採点 → 出力・印刷 → `.sao` での受け渡し）は、
web で端から端まで通るところまで来ている。

### 1. 採点の流れで残っている粗（済んだ部分は上の「組み立て方」）

| 粗                                   | 中身                                                                                                                                                                                                                                                                         |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **印刷のキャンセルを見分けられない** | ブラウザは印刷ダイアログの結果を教えない（`afterprint` も保存とキャンセルを区別しない）。web 版は「印刷ダイアログを閉じました（PDF に保存した場合は、保存先を確かめてください）」と断定せずに知らせる（`src/lib/outputResultText.ts`）                                       |
| **画像処理の間の待ち**               | wasm-vips の呼び出しは同期で、バイト列の入力では Worker のイベントループへ戻らない。答案の取り込みの補正の間は、他の要求が待たされる見込み。未実測。1枚ごとにイベントループへ戻す案は、計測してから決める                                                                    |
| **読めない画像の形式**               | wasm-vips は SVG・HEIF の追加の wasm を読まず、PDF の読み込み器も無い。模範解答の差し替えは、web 版では PDF・PNG・JPEG に絞った。解答用紙の画像要素の SVG はブラウザが描くので当たらない。BMP は両方の版で読めない                                                           |
| **表示の粗**                         | 保存先は web 版ではファイル名だけを見せる（`savedFileLocationText`）。ページ別 PDF・PNG と、解答用紙の複数ページの PNG は zip 1つにまとめる（`electron-src/lib/multiFileOutput.ts`）。解答用紙の「別ファイルに分ける」は2回のダウンロード（PDF は2回の印刷ダイアログ）のまま |

### 2. ブラウザに置いたデータを守る（必須）

- **消されないようにする（済）:** 開いたときに `navigator.storage.persist()` を頼み、得られなければ
  トーストで知らせて `.sao` での控えを勧める（`src/components/common/BrowserStorageNotifier.tsx`）。
  Chrome / Edge は尋ねずに、サイトの使われ方（ブックマーク・インストールなど）から決める。
- **容量（済）:** 設定の「ブラウザの保存領域」（web 版でだけ出す）で、保護の有無・使っている量・
  データ書き出しへの導線を見せる。上限の 8 割を超えたら開いたときにも知らせる。
- **migration の前の控え（済）:** デスクトップ版と同じく `data/` に5世代まで残す。控えは DB だけで
  画像を含まないので小さい（実測で約 3MB）。
- **新しい版で開いたとき（済）:** migration に失敗すると控えから戻し、起動を止めて理由を出す。
  ブラウザで実測した（途中で失敗・トランザクションの中で失敗・成功のあとに失敗の、どれも元に戻り、
  直した版で開き直せばデータはそのまま）。戻すときは DB のファイルを切り詰めてから書く
  （`web/worker/appDatabase.ts`。切り詰めないと、失敗した migration が伸ばした分が末尾に残る）。
- **起動できないときの案内（済）:** 理由に添えて「データはこのブラウザに残っている。サイトのデータを
  消さずに開き直す」と出す（`web/page/entry.ts`）。配っている版は1つなので、migration に失敗した版は
  開き直しても同じ失敗を繰り返すが、データは無事で、直した版を配れば開ける。
- **残り:** 戻すこと自体に失敗したときは、画面には migration の失敗としか出ず、開き直すたびに
  壊れた DB の控えが正常な控えを5世代から押し出す（デスクトップ版と共通の作り）。

### 3. 公開前のセキュリティ点検（必須）

**なぜ要るか:** web 版では、生徒の氏名・答案画像・成績のすべてが1つのオリジンの OPFS にある。
そのオリジンで任意のスクリプトが1度でも動けば、全データを読んで外へ送れる。デスクトップ版より
XSS の被害が直接になる。しかも、攻撃者が中身を作れる入力がある（他人から受け取った `.sao`、
名簿の CSV・Excel、取り込む画像・PDF、ファイル名、DB に入っている文字列）。

**観点:**

| 観点                              | 見るもの                                                                                                                                                |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. HTML・スクリプトの差し込み** | `dangerouslySetInnerHTML`・`innerHTML`・印刷の `srcdoc`・`new Function`・SVG と MathJax・HTML を文字列で組み立てる箇所・`href` に入る URL               |
| **2. 外から来るファイル**         | `.sao`（zip の中のパスと大きさ、中の SQLite）・画像と PDF・CSV と Excel。出力する CSV・Excel の数式インジェクション                                     |
| **3. web 版の実行時の境界**       | Service Worker が返す範囲と種類・`postMessage` の送り元の確かめ・ログインのパスコードが何を守り何を守らないかの整理・ダウンロードの置き場と一時ファイル |
| **4. 外への通信**                 | 外へ出る通信を全数洗い出す。無いことを CSP で縛る                                                                                                       |
| **5. 依存・ビルド・配るもの**     | 依存の既知の脆弱性・束ねたものの中身・秘密の混入・CI の権限と第三者の Action の版の固定                                                                 |

**多層の防御として入れるもの:**

- 厳しい CSP。`default-src 'self'` を基本にし、外部への接続を許さない。wasm に要るものだけを許す。
- Trusted Types を入れられるか検討する。
- `frame-ancestors`・`X-Content-Type-Options`・`Referrer-Policy`・`Permissions-Policy` を付ける。

**進め方:**

1. 観点ごとにコードを読んで点検する。
2. 見つかったものを重さで並べ、直すかどうかを1件ずつ決める。
3. 直したものは回帰テストで縛る。
4. **公開の条件は「重大・高が0件」。**

点検の結果の具体は、直すまで公開の文書に書かない。

**いまの状態:** 1巡目の点検で見つかったものは、重大・高に続いて中・低も直した。CSP などのヘッダーは
`scripts/web/webHeaders.mjs` の1か所で決め、`web:build` が `web-dist/_headers` と各 HTML の CSP の meta
（インラインのスクリプトのハッシュ）を書き出し、`web:serve` も同じものを付ける。画面では eval を許さず
（Worker だけが wasm-vips のために許す）、外部への接続も許さない。

**公開後も続けること:** 依存を更新し、既知の脆弱性を追う。新しい差し込み口（HTML の組み立て・
取り込む形式・外への通信）を足すときは、上の観点で確かめてから入れる。

### 4. 配信

- **公開の条件:** 3 の点検が済む（重大・高が0件になる）まで公開しない。

**済んだもの:**

- **`_redirects`:** `web:build` が `src/lib/routeShell.ts` の `routeShellRewriteRules` から書き出す
  （`scripts/web/webRedirects.mjs`。200 の書き換え、段ごとに3行）。手元の配信の `toRouteShellPath` と
  同じ結果になることを `__tests__/web/webRedirects.test.ts` が縛る。Cloudflare Pages では
  静的なファイルより規則が先に効くので、Next の `__next.` のファイルもそのまま通す規則を置く。
- **版の入れ替え:** 書き出しごとに版（package.json の版＋書き出した時刻）を決め、画面の入口と
  Worker に埋め込み、`/__web/build.json` にも置く（`web/webBuild.ts`）。
  - 起動時に Worker の版と画面の版が違えば（読み込む間に配り直された）、使わせずに再読み込みを頼む。
  - 開いている間は、タブが見えるようになったときと15分ごとに `build.json` を読み、違う版なら
    「新しい版があります。保存していない作業が無いことを確かめて再読み込みしてください」を出す
    （`web/page/buildUpdateNotice.ts`）。勝手には再読み込みしない。migration は再読み込みの後に走る。
  - Service Worker はキャッシュを持たないので、入れ替えは再読み込みのときの登録に任せ、
    待たずに受け持つ（`skipWaiting`）。
- **CI:** `.github/workflows/web-deploy.yml`（`main` への push と手動だけ）。書き出しは読むだけの
  権限で `npm ci --ignore-scripts` → `prisma generate` → `next build` → `web:build` →
  点検（`scripts/web/checkWebDist.mjs`。ソースマップ・DB・`.env`・手元のパス・鍵の形の文字列が
  あれば失敗）→ artifact。配る段は environment `web-production` の中だけで Cloudflare の秘密を使い、
  `wrangler pages deploy` を固定の版で走らせる。秘密が揃うまでは配る段を飛ばす。

**残り（Cloudflare・GitHub の側で人がやること）:**

1. Cloudflare Pages のプロジェクトを「直接アップロード」で作る（Git の連携はしない。書き出しは CI が行う）。
2. カスタムドメインを付ける。
3. API トークンを作る。権限は「Cloudflare Pages: Edit」だけ、対象はそのアカウントだけ。
4. GitHub の environment `web-production` を作り、承認者を付ける。そこに secrets
   `CLOUDFLARE_API_TOKEN`・`CLOUDFLARE_ACCOUNT_ID` と vars `CLOUDFLARE_PAGES_PROJECT` を置く。
   配る枝を `main` に限る。
5. ゾーンでスクリプトを差し込む機能（Web Analytics の自動差し込み・Rocket Loader・
   Email Address Obfuscation・Zaraz など）を切る。差し込まれたスクリプトは CSP に止められ、
   HTML を書き換えられるとインラインのスクリプトのハッシュも合わなくなる。
6. 配ったあとに確かめる: `_headers`（COOP/COEP・CSP。Worker の CSP の付け直し
   `! Content-Security-Policy` が効くこと）、`_redirects`（実際の id の URL で画面が開くこと）、
   版の知らせ（配り直すと開いているタブに出ること）。
7. web 版の e2e は無い。作ったら CI の書き出しの後に回す。

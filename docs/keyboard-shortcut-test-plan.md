# キーボードショートカットシステム テスト計画

## 📋 テスト概要

### 目的

新しいコマンドベースのキーボードショートカットシステムが、すべての操作モード（グリッド・個別・モーダル）で正しく動作することを確認する。

### テスト環境

- **ページ**: `/projects/[projectId]/07-score-at-once`（一括採点画面）
- **ブラウザ**: Chrome/Edge（Electronベース）
- **OS**: macOS（Option）とWindows（Alt）の両方で確認
- **前提条件**:
  - プロジェクトが作成済み
  - 模範解答がアップロード済み
  - 採点領域が設定済み
  - 受験生徒が登録済み
  - 答案画像が複数アップロード済み

---

## 🎯 テストケース一覧

### 1. 採点コマンドテスト（Scoring Commands）

#### 準備

- グリッドモードで答案を1つ以上選択した状態

| コマンドID          | デフォルトキー | 期待される動作             | チェック |
| ------------------- | -------------- | -------------------------- | -------- |
| `scoring.unscored`  | Q              | 選択中の答案が未採点になる | ☐        |
| `scoring.correct`   | E              | 選択中の答案が正答になる   | ☐        |
| `scoring.partial`   | F              | 部分点入力モーダルが開く   | ☐        |
| `scoring.pending`   | J              | 選択中の答案が保留になる   | ☐        |
| `scoring.incorrect` | O              | 選択中の答案が誤答になる   | ☐        |
| `scoring.noAnswer`  | P              | 選択中の答案が無答になる   | ☐        |

**テスト手順**:

1. グリッドモードに切り替え
2. 答案を1つクリックして選択
3. 各キーを順番に押して、採点状態が変わることを確認
4. 複数の答案を選択（Ctrlクリック）
5. 採点キーを押して、すべてが同じ状態になることを確認

**失敗条件**:

- 答案が選択されていない状態でキーを押すと、何も起こらないこと（when句で制御）
- input要素にフォーカスがある状態では動作しないこと

### 2. ナビゲーションコマンドテスト（Navigation Commands）

#### 2-1. 個別モード - 設問/生徒移動

| コマンドID                     | デフォルトキー | 期待される動作 | チェック |
| ------------------------------ | -------------- | -------------- | -------- |
| `navigation.nextQuestionArrow` | →              | 次の設問に移動 | ☐        |
| `navigation.prevQuestionArrow` | ←              | 前の設問に移動 | ☐        |
| `navigation.nextStudentArrow`  | ↓              | 次の生徒に移動 | ☐        |
| `navigation.prevStudentArrow`  | ↑              | 前の生徒に移動 | ☐        |
| `navigation.nextQuestion`      | Shift+D        | 次の設問に移動 | ☐        |
| `navigation.prevQuestion`      | Shift+A        | 前の設問に移動 | ☐        |

**テスト手順**:

1. 個別モード（individual）に切り替え
2. 最初の生徒・最初の設問を表示
3. ↓キーで次の生徒に移動することを確認
4. ↑キーで前の生徒に戻ることを確認
5. →キーで次の設問に移動することを確認
6. ←キーで前の設問に戻ることを確認
7. Shift+DとShift+Aでも設問移動できることを確認

#### 2-2. グリッドモード - WASD移動

| コマンドID             | デフォルトキー | 期待される動作 | チェック |
| ---------------------- | -------------- | -------------- | -------- |
| `navigation.moveUp`    | W              | 上のセルを選択 | ☐        |
| `navigation.moveLeft`  | A              | 左のセルを選択 | ☐        |
| `navigation.moveDown`  | S              | 下のセルを選択 | ☐        |
| `navigation.moveRight` | D              | 右のセルを選択 | ☐        |

**テスト手順**:

1. グリッドモードに切り替え
2. 任意の答案を選択
3. W/A/S/Dキーで上下左右に選択が移動することを確認
4. グリッドの端では移動しないことを確認

#### 2-3. ズーム操作

| コマンドID             | デフォルトキー | 期待される動作 | チェック |
| ---------------------- | -------------- | -------------- | -------- |
| `navigation.zoomIn`    | =              | ズームイン     | ☐        |
| `navigation.zoomOut`   | -              | ズームアウト   | ☐        |
| `navigation.resetZoom` | 0              | ズームリセット | ☐        |

**テスト手順**:

1. 個別モードで答案を表示
2. =キーを数回押してズームインすることを確認
3. -キーを数回押してズームアウトすることを確認
4. 0キーでズームがリセットされることを確認

### 3. フィルタコマンドテスト（Filter Commands）

#### 3-1. Alt + 採点キーでフィルタトグル

| コマンドID               | デフォルトキー | 期待される動作         | チェック |
| ------------------------ | -------------- | ---------------------- | -------- |
| `filter.toggleUnscored`  | Alt+Q          | 未採点フィルタをON/OFF | ☐        |
| `filter.toggleCorrect`   | Alt+E          | 正答フィルタをON/OFF   | ☐        |
| `filter.togglePartial`   | Alt+F          | 部分点フィルタをON/OFF | ☐        |
| `filter.togglePending`   | Alt+J          | 保留フィルタをON/OFF   | ☐        |
| `filter.toggleIncorrect` | Alt+O          | 誤答フィルタをON/OFF   | ☐        |
| `filter.toggleNoAnswer`  | Alt+P          | 無答フィルタをON/OFF   | ☐        |

**テスト手順**:

1. グリッドモードに切り替え
2. 複数の答案に異なる採点状態を設定（正答・誤答・保留等）
3. Alt+Eキーを押して、正答フィルタがトグルされることを確認
4. 正答のみが表示/非表示になることを確認
5. 他のフィルタキーも同様にテスト

**注意**: macOSでは「Option+キー」になる（デッドキー対応を確認）

#### 3-2. Ctrl + 数字キーでフィルタ切り替え

| コマンドID                          | デフォルトキー  | 期待される動作   | チェック |
| ----------------------------------- | --------------- | ---------------- | -------- |
| `filter.toggle1` ~ `filter.toggle6` | Ctrl+1 ~ Ctrl+6 | フィルタ切り替え | ☐        |

**テスト手順**:

1. グリッドモードで各フィルタの動作を確認
2. Ctrl+1からCtrl+6を押して、対応するフィルタがトグルされることを確認

#### 3-3. フィルタ更新

| コマンドID       | デフォルトキー | 期待される動作 | チェック |
| ---------------- | -------------- | -------------- | -------- |
| `filter.refresh` | R              | フィルタを更新 | ☐        |

**テスト手順**:

1. グリッドモードでRキーを押す
2. フィルタが再適用されることを確認

**失敗条件**:

- 個別モード（individual）ではフィルタコマンドが動作しないこと（when句で制御）

### 5. モーダルコマンドテスト（Modal Commands）

#### 5-1. 部分点入力モーダル - 数字入力

| コマンドID                      | デフォルトキー | 期待される動作         | チェック |
| ------------------------------- | -------------- | ---------------------- | -------- |
| `modal.input0` ~ `modal.input9` | 0 ~ 9          | 数字が入力される       | ☐        |
| `modal.inputDot`                | .              | 小数点が入力される     | ☐        |
| `modal.backspace`               | Backspace      | 最後の文字が削除される | ☐        |

**テスト手順**:

1. グリッドモードで答案を選択
2. Fキーを押して部分点入力モーダルを開く
3. "1", "2", ".", "5"の順に押す
4. "12.5"と表示されることを確認
5. Backspaceキーを押して"12."になることを確認

#### 5-2. 部分点入力モーダル - 確定/キャンセル

| コマンドID             | デフォルトキー | 期待される動作   | チェック |
| ---------------------- | -------------- | ---------------- | -------- |
| `modal.confirmPartial` | F              | 部分点として確定 | ☐        |
| `modal.confirmPending` | J              | 保留として確定   | ☐        |
| `modal.cancel`         | Escape         | キャンセル       | ☐        |

**テスト手順**:

1. 部分点入力モーダルで"8.5"と入力
2. Fキーを押す
3. モーダルが閉じ、部分点8.5が設定されることを確認
4. 再度モーダルを開き、"7"と入力
5. Jキーを押す
6. モーダルが閉じ、保留状態になることを確認
7. 再度モーダルを開き、Escapeキーを押す
8. モーダルが閉じ、採点状態が変わらないことを確認

### 6. コンテキスト条件テスト（When Clause Tests）

#### 6-1. inputFocus条件

**テスト手順**:

1. サイドパネルにinput要素がある場合、フォーカスを当てる
2. E、F、Jなどの採点キーを押す
3. **何も起こらない**ことを確認（入力欄に文字が入力される）
4. input要素の外をクリック
5. 同じキーを押すと採点コマンドが実行されることを確認

**期待**: `when: "!inputFocus"` により、input要素にフォーカスがある間はショートカットが無効化される

#### 6-2. gradingMode条件

**テスト手順**:

1. グリッドモード（`gradingMode == 'grid'`）:
   - WASD移動が動作する
   - フィルタコマンドが動作する
2. 個別モード（`gradingMode == 'individual'`）:
   - 矢印キー・Shift+A/Dが動作する
   - WASD移動が動作しない
   - フィルタコマンドが動作しない

#### 6-3. hasSelectedAnswers条件

**テスト手順**:

1. グリッドモードで答案を**選択していない**状態
2. E、F、Jなどの採点キーを押す
3. **何も起こらない**ことを確認
4. 答案を1つ選択
5. 同じキーを押すと採点コマンドが実行されることを確認

**期待**: `when: "hasSelectedAnswers"` により、答案未選択時は採点コマンドが無効化される

#### 6-4. modalOpen / partialScoreModalOpen条件

**テスト手順**:

1. 部分点入力モーダルを開く
2. W/A/S/Dキーを押す
3. **グリッド移動が起こらない**ことを確認
4. 0-9キーを押すと数字が入力されることを確認
5. Fキーで確定、Escapeでキャンセルができることを確認

**期待**: `when: "partialScoreModalOpen"` により、モーダル内専用コマンドのみが動作する

### 7. 設定画面テスト（Settings Page Tests）

#### 7-1. キーバインディング表示

**テスト手順**:

1. `/settings` ページを開く
2. キーボードショートカット設定セクションを確認
3. 以下のカテゴリが表示されることを確認:
   - 採点操作（6個）
   - ナビゲーション（13個）
   - フィルタ（13個）
   - 表示制御（2個）
   - モーダル操作（15個）
   - 保存（1個）
4. 各コマンドのデフォルトキーが正しく表示されることを確認

#### 7-2. キーバインディングのカスタマイズ

**テスト手順**:

1. 「正答」コマンドの編集ボタンをクリック
2. 入力待機状態になることを確認
3. "R"キーを押す
4. "R"が表示されることを確認
5. 保存ボタンをクリック
6. 一括採点画面に戻る
7. Rキーを押して正答になることを確認（Eキーは動作しない）

#### 7-3. キーの競合検出

**テスト手順**:

1. 設定画面で「正答」コマンドを編集
2. 既に使用されている"F"キーを入力
3. 保存ボタンをクリック
4. エラートーストが表示されることを確認:
   - 「キー "F" は既に "部分点" で使用されています」

#### 7-4. リセット機能

**テスト手順**:

1. 複数のキーバインディングをカスタマイズ
2. 「デフォルトに戻す」ボタンをクリック
3. 確認ダイアログが表示されることを確認
4. OKをクリック
5. すべてのキーバインディングがデフォルト値に戻ることを確認

#### 7-5. localStorage永続化

**テスト手順**:

1. 設定画面で「正答」をRキーに変更
2. ページをリロード（F5）
3. 設定画面を再度開く
4. 「正答」がRキーのままであることを確認
5. 一括採点画面でRキーが動作することを確認
